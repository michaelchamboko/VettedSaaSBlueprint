# Project Rules

## Content and release

- Work only on the public static site and owner-authored repository content.
- A publishable page needs an exact approved affiliate URL when applicable, a visible disclosure, evidence for material claims, a limitation, and a passing consolidated quality result.
- Git and Vercel are the release path: clean-worktree validation, accepted merge to `main`, Vercel build, production smoke verification.
- Keep evidence gathering bounded. Do not create an infrastructure preflight, remote capability check, database transition, or mandatory post-batch retro.

## Exclusions

- No database, authentication, admin app, API job queue, click-event ingestion, affiliate redirect, external CI automation, or release-bot machinery.
- Do not add third-party tracking, fingerprinting, raw IP storage, remarketing, newsletter capture, or profiling.
